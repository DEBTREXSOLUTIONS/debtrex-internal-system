DEBTREX — SIDEBAR PERMISSIONS FIX
==================================

WHAT THIS FIXES
===============

Even with all permissions ON for your custom role, several sidebar
sections were missing. Three bugs caused this:

1. Sidebar had HARDCODED role checks for some items that bypassed
   the permission system entirely (Twilio Numbers, Custom Roles)
   
2. Server pages had hardcoded isLeadership() checks too, so even if
   the sidebar link showed, the page would redirect non-leadership
   users back to home

3. Sidebar was never being passed any permissions, so it always
   used role-based defaults instead of the actual permission toggles


THE FIX
=======

A. Sidebar now fetches your actual permissions from /api/me/permissions
   when it loads, so it shows exactly what your role is allowed.

B. New permission keys added:
   - section.twilio_numbers   (was hardcoded isLeadership)
   - section.custom_roles     (was hardcoded isLeadership)
   - roles.manage             (was hardcoded isLeadership)

C. Server pages now check these permissions instead of hardcoded roles.

D. Migration seeds the new permissions for all existing roles.


APPLY ORDER
===========

STEP 1 — RUN MIGRATION-006.SQL IN SUPABASE
  
  Open Supabase → SQL Editor → New query
  Paste contents of database/migration-006.sql
  Click Run
  
  This adds the 3 new permission rows for every role in your system.
  Built-in leadership roles get them ON. All other roles get them
  seeded OFF (you can flip them on from /permissions).

STEP 2 — DROP THE 7 FILES IN

  database/migration-006.sql                          [NEW]
  lib/permissions.ts                                  [REPLACE]
  components/Sidebar.tsx                              [REPLACE]
  app/twilio-numbers/page.tsx                         [REPLACE]
  app/roles/page.tsx                                  [REPLACE]
  app/team/page.tsx                                   [REPLACE]
  app/api/me/permissions/route.ts                     [NEW]

STEP 3 — TURN ON PERMS FOR YOUR "SYSTEM" ROLE

  - Sign in as CEO
  - Sidebar → Admin → Permissions
  - Find the "system" column
  - In the "Section Visibility" group, toggle ON:
      * section.twilio_numbers
      * section.custom_roles
      * (any others you want — section.budget, section.team, etc.)
  - In the "Permissions Admin" group, toggle ON:
      * roles.manage
      * permissions.manage (if you want them to admin perms too)
  - Click Save All Changes

STEP 4 — TEST

  - Log out
  - Log in as a user with the "system" role
  - Sidebar should now show all the sections you toggled on
  - Click into Twilio Numbers and Custom Roles to confirm access

STEP 5 — PUSH TO PRODUCTION

  git add .
  git commit -m "Fix sidebar permissions for custom roles"
  git push


HOW SIDEBAR PERMISSIONS NOW WORK
=================================

When any page renders, the Sidebar component:
  1. Mounts in the browser
  2. Calls /api/me/permissions to fetch THIS USER's permissions
  3. Uses those to decide which links to show

This means:
  - Every link in the sidebar respects the Permissions page toggles
  - Custom roles work without any code changes
  - Changes you make on /permissions take effect after a 5-minute cache
    (or instantly for the user who made the change)


WHY YOU SAW MISSING SECTIONS BEFORE
====================================

Three different code paths were involved:

  Section            How it gated access (OLD)         Now
  ─────────────────  ───────────────────────────────  ─────────────────
  Dashboard          can('section.dashboard', true)    Same (permission)
  Tasks              can('section.tasks', true)        Same
  Sales              can('section.pipeline_sales')     Same
  Management         can('section.pipeline_management')Same
  Performance        can('section.performance')        Same
  Budget             can('section.budget')             Same
  Team               can('section.team')               Same
  Twilio Numbers     isLeadership(user.role)  ❌       can('section.twilio_numbers')
  Custom Roles       isLeadership(user.role)  ❌       can('roles.manage')
  Permissions        can('permissions.manage')         Same

So Twilio Numbers and Custom Roles were never togglable. Now they are.
