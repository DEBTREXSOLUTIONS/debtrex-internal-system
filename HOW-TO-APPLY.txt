DEBTREX — AGENT STATUS + INBOUND CALLING
==========================================

WHAT THIS PATCH ADDS
====================

1. AGENT STATUS — Everyone in the system gets a 5-state status they
   can change anytime from the top bar:
     • ONLINE      — Available for calls and tasks
     • OTL         — On The Line (currently on a call)
     • MEETING     — In a meeting, do not disturb
     • BREAK       — Away for a short while
     • OFFLINE     — Not working
   
   Status auto-sets to ONLINE on page load, and OFFLINE when you
   close the browser tab.

2. INBOUND CALLS — Customers can call your Twilio numbers and:
     • Get routed to a specific agent (rings their browser)
     • Get routed to ANY available (online) agent
     • Go straight to voicemail (recorded + saved to call_logs)
   
   Routing is configured per-number from the Twilio Numbers admin page.
   When a call comes in, a full-screen incoming-call UI pops up over
   any page the agent is on. They can answer, decline, mute, or
   keypad-tone during the call.


HOW IT WORKS — INBOUND CALL FLOW
=================================

1. Customer dials one of your Twilio numbers
2. Twilio hits your /api/twilio/inbound webhook
3. Our code looks up routing for that number:
     - "Specific Agent" mode → check if agent's status is "online"
       If yes → ring their browser via <Client>{agentId}</Client>
       If no  → straight to voicemail
     - "Available" mode → query all profiles where status='online'
       Ring all of them — first to answer wins
     - "Voicemail" mode → Twilio plays greeting + records
4. Agent's browser (which is registered with Twilio via Voice SDK)
   shows the incoming call UI
5. Agent clicks Answer → audio flows through computer mic/speakers
6. Call ends → logged to call_logs with recording


PREREQUISITES (you already have these)
=======================================

  TWILIO_API_SECRET, TWILIO_TWIML_APP_SID)

STEP 3 — CONFIGURE TWILIO CONSOLE FOR INBOUND
==============================================

For EACH Twilio number you want to receive calls on:

  1. console.twilio.com → Phone Numbers → Active Numbers
  2. Click the number
  3. Scroll to "Voice Configuration" section
  4. Under "A call comes in":
       Configure with:   Webhook, TwiML Bin, Function...
       URL:              https://debtrex-internal-system.vercel.app/api/twilio/inbound
       Method:           HTTP POST
  5. Scroll down → Save Configuration
  6. Repeat for each number

TROUBLESHOOTING
===============

"Status doesn't save"
  → Check that migration-007 ran. Visit /api/me/status — should
    return your current status without an error.

"Incoming call UI never appears"
  → Multiple things to check:
    1. Make sure your status is "Online" (top bar status picker)
    2. Browser must have microphone permission for your DEBTREX site
       Check via lock icon in address bar
    3. The Voice SDK device registers when the page loads. If you
       just logged in, give it 5-10 seconds before testing
    4. Check Twilio Console → Monitor → Logs → Calls — find the
       call. Click it. Look at "Request Inspector" for errors
    5. Visit /api/twilio/diagnostics (signed in as CEO) to verify
       all Voice SDK env vars are set
    6. Open browser console (F12) — look for Twilio Device errors

"Call rings but I can't hear them"
  → Wrong microphone or speaker selected. Check Chrome settings:
    chrome://settings/content/microphone

"Configured routing but calls still go straight to voicemail"
  → If routing mode is "Specific Agent", that agent's status must
    be "online" in DEBTREX. Check top bar status picker.
  → For "Any Available" mode, at least one agent must have status
    "online". Check the Team page or query: 
    select full_name, status from profiles where is_active = true;

"Inbound webhook not getting called"
  → Verify Twilio Console webhook URL is set correctly on the
    Phone Numbers page. URL must be the FULL https URL with
    /api/twilio/inbound. Method must be POST.


STATUS BEHAVIOR
================

- Loads from server on every page navigation (cached for speed)
- Set to "online" automatically when you load any page
- Set to "offline" automatically when you close the browser tab
- Inbound routing in "Specific Agent" mode ONLY rings the assigned
  agent if their status is "online" — otherwise voicemail
- Inbound routing in "Any Available" mode rings ALL profiles where
  status='online' — multiple browsers ring at once, first wins
- Status displays in the top bar with a colored dot
- Status changes are visible to other team members on the Team page


EXTENDING THIS
==============

Want to broadcast status changes in real-time so others see them
update without refreshing? You'd add Supabase Realtime subscriptions
on the profiles table — out of scope for this patch but trivial to
add later.

Want voicemail notifications? When /api/twilio/voicemail receives
a recording, send an email via Resend to the routed agent.

Want to track which agent received a call in "Available" mode?
Twilio's <Dial> sends a "DialCallSid" parameter when answered —
you'd update call_logs.user_id from that webhook.
