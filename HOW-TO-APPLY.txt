DEBTREX — MULTI-AGENT TWILIO NUMBERS
=====================================

WHAT THIS FIXES
===============

Your original question: "shouldn't each agent have their own number?"

Answer: With this patch, YES. Each agent on your Twilio account
can be assigned their own Twilio phone number, used as the caller
ID when THEY make outbound calls. Leads see different numbers
depending on which agent called.

If an agent has NO assigned number, they use the company default
(TWILIO_PHONE_NUMBER env var).

ALSO INCLUDED:
- "Call Now" button now always shows (when you have permission)
  with a clear tooltip explaining if it's disabled
- Yellow banner appears explaining exactly what's missing
- New /api/twilio/diagnostics endpoint for debugging config


HOW IT WORKS NOW
================

Agent makes a call:
  1. Agent clicks "Call Now" on a contact
  2. Server looks up the agent's assigned Twilio number
     (or falls back to TWILIO_PHONE_NUMBER if none assigned)
  3. Twilio rings the agent's PERSONAL phone first
     (from Settings → Profile)
  4. Agent picks up
  5. Twilio dials the lead and bridges them
  6. Lead sees the agent's assigned Twilio number as caller ID
  7. Call recorded, logged, etc.

The agent's PERSONAL phone is never exposed to the lead.


STEPS TO APPLY
==============

STEP 1 — RUN THE DATABASE MIGRATION

  Open Supabase → SQL Editor → New query
  Paste contents of database/migration-004.sql
  Click Run

  This adds 4 columns to profiles table:
    - twilio_phone_number    (the Twilio number assigned to this agent)
    - twilio_phone_label     (cosmetic label like "NYC line")
    - twilio_phone_assigned_at
    - twilio_phone_assigned_by

STEP 2 — DROP IN THE FILES (10 files)

  database/migration-004.sql                          [NEW]
  lib/twilio.ts                                       [REPLACE]
  components/Sidebar.tsx                              [REPLACE]
  app/pipeline/ContactDetail.tsx                      [REPLACE]
  app/twilio-numbers/page.tsx                         [NEW]

  app/api/twilio/diagnostics/route.ts                 [NEW]
  app/api/users/[id]/twilio-number/route.ts           [NEW]

STEP 3 — RESTART AND ASSIGN NUMBERS

  npm run dev
  Sign in as CEO
  Sidebar → Twilio Numbers (new section)

  You'll see:
    - List of all numbers on your Twilio account (auto-loaded)
    - List of all agents with their current assignments
    - "Edit" button next to each agent
      → Pick a Twilio number from the dropdown
      → Give it a label like "NYC line" (optional)
      → Save

STEP 4 — REQUIRED PER AGENT

  Each agent must ALSO have their PERSONAL phone in
  Settings → Profile. This is the phone Twilio rings when they
  click "Call Now". Without it, they can't make calls.

STEP 5 — PUSH TO PRODUCTION

  git add .
  git commit -m "Add per-agent Twilio numbers"
  git push


HOW TO BUY MORE TWILIO NUMBERS
==============================

If you don't have enough numbers for all your agents:

  1. Go to console.twilio.com → Phone Numbers → Buy a number
  2. Pick area codes matching your call regions (better answer rates)
  3. Buy them
  4. Return to /twilio-numbers in your app
  5. The new numbers appear automatically
  6. Assign them to agents

Cost: ~$1.15/month per local US number.


TROUBLESHOOTING
===============

"Call Now button still hidden"
  - Check yellow banner at top of contact page — it tells you exactly what's missing
  - Visit /api/twilio/diagnostics in your browser (as CEO/Owner) for full config status

"Number is already assigned to another agent"
  - Each Twilio number can only be assigned to ONE agent at a time
  - Unassign it from the current agent first

"Agent's call ID shows the wrong number"
  - Make sure you assigned a number on the /twilio-numbers page
  - Save changes — refresh the contact page
  - First call after assignment uses the new caller ID

"Twilio Numbers page shows '0 numbers on account'"
  - Twilio env vars (TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN) might be wrong
  - Restart dev server after changing env vars
  - Visit /api/twilio/diagnostics to verify
