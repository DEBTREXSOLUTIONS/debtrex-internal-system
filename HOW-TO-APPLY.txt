DEBTREX — TAB GLITCH + SIDEBAR FIXES
=====================================

THREE BUGS FIXED IN THIS PATCH
==============================

1. TAB CLICKS WERE RESETTING / PAGE GLITCHING
   Root cause: 18 buttons across ContactDetail, PipelineList, Sidebar,
   and BrowserDialer were missing type="button". When a button has no
   type, browsers default to type="submit". If the button is anywhere
   inside a form (even deeply nested), clicking it submits the form
   and reloads the page — wiping all state.
   
   Fix: Every <button> in client components now has explicit type="button"
   except actual form submit buttons which have type="submit".

2. SIDEBAR FLICKERED ON EVERY PAGE NAVIGATION
   Root cause: Sidebar fetched permissions from /api/me/permissions
   every time it mounted (which is every page load). The brief
   "loading then loaded" state caused visible flicker, and on slow
   connections links would briefly disappear.
   
   Fix: Permissions now cached in sessionStorage for 5 minutes per user.
   First page load fetches; subsequent navigations are instant. The
   cache clears when you close the browser tab, so role changes still
   take effect on next session.

3. MANAGER ASSIGNMENTS NOW A PROPER NAV ITEM
   Was a tiny mini-link that appeared only when on Performance pages.
   Now a regular nav item in the "Team" section. Always visible to
   roles with the performance.assign_managers permission.

4. SIDEBAR ACTIVE STATE FIXED
   When on /performance/assignments, both "Performance" and
   "Manager Assignments" were highlighted. Now only the most
   specific matching item gets the red highlight.

5. SIDEBAR COLLAPSED STATE PERSISTS
   Which sections you collapse are now saved to localStorage.
   Stays the same across page loads and browser sessions.

DEBUGGING THE MISSING TWILIO NUMBERS SECTION
==============================================

1. Open this URL in your browser (signed in as the user with the role):
   https://debtrex-internal-system.vercel.app/api/me/permissions

2. Find the section_visibility object in the JSON response

3. Look for: "twilio_numbers": true/false

4. If "section.twilio_numbers" doesn't even appear in the permissions
   object → migration-006 didn't run. Run it in Supabase SQL Editor.


WHY YOU CAN TRUST THIS FIX
============================

The button type bug is a CLASSIC React gotcha:
  <button onClick={...}>Hello</button>  ← submits any parent form
  <button type="button" onClick={...}>Hello</button>  ← safe

When you had the contact in edit mode (with a form visible somewhere),
ANY button click anywhere — even tabs — could trigger a form submit
through the bubbling event. This caused the page to reload completely,
which reset:
  - The active tab
  - Any unsaved form data
  - The scroll position
  
This was likely the source of your "glitching" report. Now solved
defensively across 5 client components.


SIDEBAR FETCH FLOW (FOR YOUR REFERENCE)
========================================

Old:
  Page loads → Sidebar mounts → calls /api/me/permissions
  → waits for response → shows correct links
  (Repeated every page click — caused flicker)

New:
  Page loads → Sidebar mounts → reads cache from sessionStorage
  → shows correct links INSTANTLY
  → if cache is older than 5 min, fetches in background to refresh
  (No flicker after first page load)
